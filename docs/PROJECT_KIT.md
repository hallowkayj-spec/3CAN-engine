# 3CAN Project Kit

Use this package when copying 3CAN into a new local project without bringing
over another project's graph, token ledger, or private runtime state.

The release package intentionally ships with an empty
`neural-memory/graph/` directory. The generic base graph is generated by
`neural-memory/backend/seed_nodes.py` during setup, and each project owns its
own runtime graph after initialization.

## Windows Quick Start

From the target project root:

```powershell
..\3CAN-engine\scripts\init-project.ps1 -ProjectDir . -Port 9711 -StartServer
```

The script sets:

- `THREECAN_ENGINE_ROOT` to the sidecar engine directory
- `THREECAN_GRAPH_DIR` to the sidecar graph directory
- `THREECAN_PROJECT_DIR` to the target project
- `THREECAN_BASE_URL` to `http://127.0.0.1:<port>`
- `THREECAN_MIN_NODES` to `10` for fresh project graphs

Open:

- Gateway: `http://127.0.0.1:9711`
- Token dashboard: `http://127.0.0.1:9711/static/token_usage.html`

Verify:

```powershell
python ..\3CAN-engine\scripts\verify_project.py --base-url http://127.0.0.1:9711 --min-nodes 10
```

The verifier checks liveness, deep `/api/stats` readiness, `/api/route`, and
token-usage health. A fresh graph is explicitly initialized in
`development` readiness mode. Use `--require-production-ready` only with a
pinned production profile.

## Dependency Profiles

- `requirements-min.txt`: minimal backend, seed, route, and verification path.
- `requirements-full.txt`: semantic stack extras such as `sentence-transformers`,
  community detection, and reranker fallback.
- `requirements.txt`: historical full dependency file kept for compatibility.

## Codex Kit

Copy `examples/codex-cli-project-kit/` into the target project, then rename
`AGENTS.template.md` to `AGENTS.md` and adjust the port if needed.

The kit includes optional adapters:

- `scripts/codex-3can.*`
- `scripts/3can_codex.py`
- `scripts/3can_pr_harness.py`
- standing-order and task-ledger helpers
- the 3CAN deep-research skill
- `.codex/` hook config

Read-only routing does not require a ticket, check-in, hook, or wrapper. Use the
prepare/done lifecycle only when a project has a concrete guarded-write or
evidence requirement. The wrapper never starts or terminates backend/proxy
processes. Explicit `-StartServer`/`--start-server` is an operator setup
action; a managed Windows installation may instead expose one Scheduled Task
to the wrapper.

## Optional GitHub PR Fallback

If `gh` is unavailable or a GitHub connector cannot create a PR for a private
repository, use the local PR harness:

```powershell
python scripts\3can_pr_harness.py check
git push -u origin <branch>
python scripts\3can_pr_harness.py create-pr `
  --approval-id <user-approval-id> `
  --title "PR title" `
  --body-file .\PR_BODY.md `
  --base main
```

The hook-backed ERR node is
`ERR-20260508-github-pr-local-rest-fallback-required`. This is intentionally an
error lesson, not only a how-to doc, so route/prepare can surface it before the
same PR mistake repeats.

## Pre-Release Scan

Run this before copying or publishing:

```powershell
python ..\3CAN-engine\scripts\prerelease_scan.py --strict
```

Default scan mode fails on high-confidence secrets and reports path rebinding
warnings. `--strict` also fails on maintainer-local absolute paths and private
project names.

Strict mode also fails if runtime graph artifacts such as node JSON, SQLite
ledgers, embeddings, activity logs, or agent state are present inside the
release package.
