Workorder：`RUNTIMEHOOK-TEMPORARY-CN-20260914`。维护者：RuntimeHook maintainer。
候选版本：`0.1.7-rc.1`。状态：`COMPONENT_VERIFIED / NATIVE_EVENT_PENDING`；不代表业务内容验收或所有任务已热加载。

## 请求与实现边界

用户要求同一任务中能临时插入相关交付，完成后必须清除临时监督并返回主目标；
任务转移或疑似偏移只给建议，全部 Hook 阐述使用中文。

采用现有控制器和同一状态文件，不创建子进程型 Hook、任务管理器、任务栈、调度器或新的网络依赖。
新增一个可选临时任务槽，保存临时目标、验收、用户依据与返回主任务后的下一步。
Agent 基于当前用户要求判断关系；没有提示词关键词分类器，也不把用户明确变更当作自动漂移。

临时最终复核通过时，一个原子保存同时清除临时槽并恢复主任务下一步；
主目标、activation 和 scope 绑定保留，主任务为阶段 PARTIAL，不能复用此前主任务最终 PASS。
显式 `--scope temporary` 防止重复收尾误变成主任务最终 PASS。
未完成/失败/缺少输入保留临时状态；只有用户明确取消才能非成功清除。
既不按时间自动取消，也不从“计划步骤完成”或回复文本猜测真实产出已验收。

临时产出不强迫提交主任务未完代码；主任务最终 PASS 的干净 Git 检查点要求保持不变。
真正的产出证据、浏览器安全检查、凭据、发布与项目严格验证仍由各自既有机制负责。

官方依据：[Stop Hook](https://learn.chatgpt.com/docs/hooks#stop) 的 `decision:block` 是续行请求，
不是拒绝整个任务。本变更只在尚欠边界复核或主任务最终 PASS 过期时请求一次续行；
当前阶段已有真实复核时，中途回复/必要等待不再强制变成整体最终验收。
转移/漂移命令仅返回中文建议，不创建任务、不迁移目录、不改变语义状态。
新任务只隔离对话；需要并行写入时仍应有独立 worktree。

## 版本与上线边界

普通状态仍为 v1；仅临时槽生效时写 v2。新控制器读 v1/v2；旧控制器不能将 v2 当作主任务继续写入。
Windows PowerShell 5 的中文启动器使用 UTF-8 BOM，管道继续显式 UTF-8；协议字段和命令不翻译。
现有记录中的用户原文、路径和机器状态码不进行猜测翻译。

通过既有本地 marketplace 和原生插件安装器更新，保留旧缓存路径供已加载任务使用；
安装不等于已运行任务热加载。没有迁移任务、关闭其他 Hook、停止业务任务或重启 9700/9711/17890。
回滚前用新版本完成或按用户要求取消临时任务，使状态返回 v1；不可强制降级或删除临时现场。
独立安全门禁不能通过临时模式或取消操作绕过。
