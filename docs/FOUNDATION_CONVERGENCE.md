# Foundation convergence

Status: IN PROGRESS. This is a delivery record, not an acceptance assertion.

## Owner contract

Converge existing 3CAN capabilities using current open-source evidence, then
verify and deploy the engine, client guidance, native hooks and graph frontend.
Preserve graph data, independent runtime identities, credentials, single-writer
boundaries and unrelated project work. Research must improve engineering
decisions; semantic review must inspect actual outcomes. Do not create another
task runtime, evidence kernel or unconditional research gate.

## Evidence boundaries

Unit tests do not establish native Codex hook delivery. Native hook delivery
does not establish semantic output quality. Service liveness does not establish
production readiness or sustained business success. Open-source comparisons are
capability/architecture comparisons unless a controlled benchmark was run.

## Initial local observations

The production Supervisor verified its existing owner after reboot; the owner
served 2,655 nodes and 1,035 edges with verified BGE-M3 embeddings. The separate
development sidecar was started through its existing NoSeed operator entry and
reported 19 nodes, 10 edges, development-ready and not production-ready. These
are time-specific observations, not minimums to hardcode into clients.

Public main and several open feature branches differ. Integration starts from
the existing RuntimeHook plugin candidate and must retain error governance and
client-context changes rather than replacing the runtime with an older base.
