## Installation findings and rollout

The global Plugin's former Windows command used cmd syntax, while native Codex
selected PowerShell. Existing Python `shell=True` tests chose cmd and concealed
the mismatch. A quote-free transport experiment also failed, ruling out the
initial cmd-quoting hypothesis as the local cause. The final Plugin invokes one
PowerShell script directly. The batch wrapper and encoded experiment were
removed. Legacy Project Kit commands had a related nested-shell interpolation
failure; exact native-shell reproductions failed before the fix and passed after
removing the unnecessary second shell. No daemon, retry queue or permission
bypass was introduced.

Global AGENTS.md, the machine 3CAN.md guide and research Skill were backed up and
updated. Research remains evidence-to-decision work; there is no unconditional
research gate on ordinary edits. RuntimeHook checks actual output against
criteria and does not turn rendering, a ledger or passing tests into semantic
acceptance. Existing project-owned evidence/credential/publication gates remain
independent. Unrelated worktrees and their local hook definitions were not
silently overwritten.

The 9700 rollout used an immutable HTML release and the existing canonical
Supervisor. Its first exact-stop attempt saw a briefly retained TCP listener
tuple, failed before selector publication, and restored the prior owner. A
bounded exact-PID drain check then allowed the second cutover to complete.
Original failure and rollback receipts are retained. Production live/deep
checks passed after deployment; the pinned dense BGE-M3 cache remains verified
and synchronized. Backend, dependencies and graph location were unchanged.

The separate 9711 owner was preserved. Its HTML was replaced atomically with
backup, without a second restart. It remains development-ready and explicitly
not production-ready; the readiness endpoint's HTTP 503 is expected for this
mode. Both ports serve HTML SHA-256
`42907e1931b3068d5355fbea38d4ef89ce05da73c0c53735605d658936ec53fb`.

Closeout also reproduced a caller-side writeback problem: PowerShell normalized
an opaque CAS timestamp from UTC to local time. The engine correctly rejected
the differently formatted version. Fresh raw readback proved unchanged content;
preserving the exact wire string allowed the one supported retry. The server
recorded the first refusal in existing issue intake, so no duplicate client
observation was sent. Guidance now explicitly preserves opaque version tokens.
The guidance change invalidated the prior benchmark's exact source hash. The
small isolated benchmark was rerun rather than relabeling the old measurement;
both dated runs remain available. Final release-manifest checks also removed
the obsolete batch wrapper from the required-file list.

## Remaining acceptance boundaries

- Source integration and local rollout do not merge public main or existing
  PRs. The consolidated candidate remains subject to Owner review and its own CI.
- New tasks or safely reopened paused tasks should load the updated native
  definition. Existing running tasks are not proven to hot-reload it.
- A Git checkpoint or supported plan/episode event can trigger review timing;
  a semantic stage without an observable event still requires the Agent's
  explicit checkpoint. This is not universal interception of every MCP action.
- Actual RPA uptime, video quality, provider completion and cross-model
  superiority remain separate business acceptance tasks. They were not resumed.
- Non-default Windows cmd/Git Bash hook shells were not validated. The current
  native Windows PowerShell path was exercised end to end.
- The existing PolyForm Noncommercial license is unchanged: public source
  availability is not OSI-approved open-source licensing.

Private operator receipts, before/after files, raw native events, test output,
failed attempts and screenshots are retained outside the public release.
