## 诊断与最小实现

现场审计节点仍以`content.extra.project_identity`保存完整项目身份；canonical Project Kit的`_compact_note_payload`也写此格式。RuntimeHook写回和notes维护却只检查顶层字段，因此合法同项目节点被拒绝。这是消费者格式不一致，不是节点缺身份或工作区需要借用。

在现有`runtimehook_notes`中保留一个小型严格解析入口，供普通写回、notes维护及归档恢复复用。规则如下：

- 接受完整顶层`project_id/project_namespace`或完整嵌套`project_identity`；两处同时声明时必须完整且一致。
- 不跨层拼凑半对身份；不猜缺失字段、不以名字/cluster/namespace别名代替完整项目对；畸形或冲突直接拒绝。
- 节点的历史workspace不是当前执行workspace。共享同项目知识节点可以跨合法工作区接续，但写入事件仍绑定本任务自己的Agent、Workorder和已核验workspace。
- 原节点元数据不因兼容而被改写。精确节点ID、Runtime身份、CAS版本、现有秘密过滤、票据和归档完整性检查仍生效。
- 不导入GraphEngine用于轻量客户端；其检索适用性解析支持更多候选字段，不能直接代替写入授权边界。继续使用标准库，无新依赖、服务或后台队列。
