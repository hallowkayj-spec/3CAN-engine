# 3CAN Capability Matrix, 2026-05-08

This matrix describes the release-staging package, not the private dogfood
graph. Status values are intentionally conservative.

| Area | Status | What Works | Boundary |
| --- | --- | --- | --- |
| Project graph substrate | Stable preview | Typed nodes and edges for sessions, decisions, errors, interfaces, skills, processes, and feedback | Graph quality depends on human/agent writeback discipline |
| Route API | Stable preview | `/api/route` supports skeleton/slim/full modes, token budget trimming, confidence metadata, query expansion, and route activity logging | Precision is not guaranteed; low-confidence route should trigger retry or research |
| Writeback | Stable preview | Activity logging, compact continuation notes, session writeback, node create/update, hash-chained activity entries | No multi-tenant auth or permission model |
| Codex CLI project kit | Preview | Bootstrap, prepare/done/compact pseudo-hooks, route tickets, token estimates, research harness, task ledger helpers | Native Codex hooks are still runtime-dependent; wrappers remain explicit discipline |
| GitHub PR harness | Preview | ERR-backed hook blocks known-bad connector/`gh` PR paths and creates PRs through local REST with approval | Requires GitHub token or Git Credential Manager/wincred; manual browser URL remains fallback |
| Claude Code hook examples | Preview | Cold-start, pre-tool, post-tool, prompt observer, pre-compact, session-end examples | Examples require user review before enabling in a real workstation |
| Standing orders | Preview | Route before edit, high-risk approval checks, failure-loop detection, task states | Current enforcement is helper-based, not a universal platform policy |
| Token operations | Preview | Local event ledger, Codex runtime status import, source/session/model/task/date rollups, fresh vs cached input, dashboard | Exact provider billing still depends on provider runtime telemetry |
| Multi-project sidecar | Preview | Per-project port, graph dir, token DB, project dir, min-node threshold, init scripts | No central port registry yet; users must avoid collisions manually |
| Release hygiene | Preview | Strict scanner blocks secrets, local paths, and runtime graph artifacts | Scanner is pattern-based; human review remains required |
| Query expansion | Experimental | Domain aliases and available local synonym adapters improve route recall | Chinese semantic expansion and reranking need more validation |
| RPA support role | Substrate only | Can record RPA tasks, evidence, failures, adapters, and KB promotion decisions | 3CAN is not itself a crawler, browser automation stack, or data-cleaning pipeline |
| Public benchmark | Not yet | Internal dogfood and smoke tests exist | No independent public benchmark claims should be made |
| Enterprise deployment | Not yet | Localhost-first HTTP service | No auth, RBAC, tenant isolation, audit export policy, or hosted deployment package |

## Practical Capability Statement

3CAN is useful today when the problem is:

- multiple coding agents repeatedly touching the same project,
- long-running work where decisions and mistakes need durable memory,
- cross-session route precision and handoff discipline,
- separating project context from raw LLM chat history,
- tracking token pressure and context efficiency,
- making project-specific RPA/backend work auditable without committing private
  runtime data.

It is not ready to claim:

- autonomous project management,
- universal RPA automation,
- guaranteed token reduction across every coding shell,
- enterprise-grade memory governance,
- public benchmark superiority.

## Update Notes

The 2026-05-08 package hardens the release boundary:

- release graph is empty by default,
- seed graph is generated by code,
- runtime artifacts are scanner-blocked,
- project kit supports isolated sidecar setup,
- token dashboard is project-local,
- GitHub PR failures are captured as recallable ERR plus hook behavior,
- CI smoke uses a temporary graph and route check.
